Проверка выполнена 18 октября 2026 года в ветке `feature-site-preflight`, созданной от актуальной `feature-calculator-discovery` / `c9773be229118e97a6aca3e398e822bae79b16a0`. Локальная среда: Node.js v24.19.0.

**Результат:** все локальные проверки прошли. Содержимое существующего сайта не изменено. В `main` не объединено, сайт и домен не публиковались/не настраивались; внешние кабинеты и счётчики не подключались.

- `tests/test-preflight.mjs` — самотесты аудитора.

Дополнительно в `docs/release-preflight/` сохранены этот отчёт и протоколы текущего прогона.

## Найденная ошибка и исправления

Первоначальный скрипт ошибочно требовал от `cookies.html` canonical на сам старый адрес. Эта страница намеренно переводит пользователя к `privacy.html#cookies`, поэтому canonical на `privacy.html` корректен и сохранён. Ошибка была в новом аудиторе, не в HTML сайта. [Первоначальный результат](initial-static-report.json).

Исправлена проверка legacy-перехода: ожидаются meta refresh и `location.replace` на нужный раздел политики, существование целевого файла/якоря и canonical без фрагмента. Добавлены регрессионные тесты для правильного перехода, неправильной цели, canonical и отсутствующего раздела.

При доработке закрыты связанные пробелы аудитора: проверяется кратность canonical, description, title и robots; повторяющиеся ID и недостающие внутренние якоря; неожиданное `noindex` распознаётся и при верхнем регистре имени метатега. База сайта определяется по canonical главной и не зависит от порядка sitemap; некорректная база выдаёт диагностику вместо исключения.

Пять исходных сценариев самотестов сохранены, общее число проверок увеличено до **22**, все прошли.

## Предупреждение, не исправлявшееся этим пакетом

`robots.txt` расположен внутри `/alexander-kravets-site/`, а не в корне хоста. Аудитор выводит предупреждение о необходимости отдельно предоставить sitemap поисковой системе после подтверждения прав. Это не ошибка текущего набора URL и не означает запрет индексации. Корневой robots.txt, canonical, sitemap, CNAME и адрес сайта не менялись.

Подключение `formularosta.eu.org`, доступ к Google Search Console / Яндекс Вебмастеру и фактическая индексация в этом этапе не проверялись и не считаются подтверждёнными.

## Повторное применение и сохранность файлов

Сразу после установки повторный запуск исходного установщика дал `ADDED: 0 files`, `--check` — `NEEDS APPLY: 0 files`, код 0. [Протокол](installer-repeat.json).

После исправления аудитора исходный установщик повторно запущен: он ожидаемо отказался перезаписывать отличающийся `scripts/check-site.mjs` с кодом 2. Хеши всех пяти установленных файлов до/после совпадают — ничего не добавлено и не перезаписано, дубли отсутствуют. Это срабатывание защиты установщика, не провал проверок сайта. [Вывод защиты](installer-protection.txt).

`git diff` относительно базы подтверждает отсутствие изменений любых прежних отслеживаемых файлов. Отдельно сохранены SHA-256 нормализованного Git-содержимого HTML кейсов, формул, UI калькулятора, общих CSS/JS, политики, главной, услуг и sitemap в [results.json](results.json). Никакие подтверждённые метрики, формулы, контакты, стили или содержимое страниц для прохождения аудитора не подгонялись.

## GitHub Actions и границы проверки

Workflow проверен по содержимому и совпадает с файлом из архива. Триггеры — PR в `main` и `workflow_dispatch`; разрешение — только `contents: read`. Используются `actions/checkout@v4` и `actions/setup-node@v4`, Node 22. Все `run`-шаги — локальные проверки. Шагов deploy/merge/push, записи секретов и настройки Pages нет.

Workflow в GitHub в этом этапе не запускался; результат CI не заявляется. Локальные команды выполнены на указанной выше версии Node, запуск на Node 22 будет происходить в настроенном workflow.

`check-live.mjs` с адресом сайта **не запускался**: эта ветка не опубликована. Выполнен только `node --check scripts/check-live.mjs`. Реальных HTTP-проверок опубликованной версии, домена и поисковых кабинетов в этом этапе не было.

Браузерные проверки **не повторялись**. Ранее сделанные скриншоты и браузерные результаты остаются в [отчёте discovery](../calculator-discovery-review/README.md) и [отчёте графиков/калькулятора](../case-calculator-review/README.md); они не выдаются за новый прогон.

Аудитор проверяет статические метаданные и ссылки, а не полную HTML-валидность, соответствие JSON-LD правилам rich results, HTTP-ответы или позиции в поиске. Проверка текущего XML отдельным стандартным парсером не является проверкой полной XML-схемы внутри Node-аудитора.
