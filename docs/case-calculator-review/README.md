# Графики кейсов и калькулятор экономики отдела продаж

Ветка `feature-case-charts-and-sales-economics`, база — `feature-ip-footer` / `471544fdab9d9fbeac67fc94916783bfc29d08c0`.

Пакет применён установщиком `apply_all.py` из предоставленного архива во временной папке вне репозитория. После установки выполнена точечная интеграция новых страниц и исправлены обнаруженные проблемы. В `main` не объединено. Домен и GitHub Pages не изменялись; сайт не публиковался. Старую отдельную ветку калькулятора не объединяли.

## Реализация

- Пять кейсов получили HTML/CSS-графики без библиотек, изображений, SVG и дополнительного JavaScript. Существующий контент кейсов и SEO-метаданные сохранены. У каждого графика видимые значения, пояснение знаменателя и диапазона, шкала начинается от нуля.
- Фарма: +25% выручки и +30% объёма в упаковках за последние два месяца проекта к сопоставимому периоду прошлого года. Квартальные показатели не объединены с ними в ряд. Точных месячных сумм фарм-направления и конфиденциальных названий компаний не добавлено; в графике только опубликованные проценты.
- Удалённый отдел: 134% / 150% выполнения каждого месячного плана, шкала 0–160% и отметка 100%; 33 договора подписаны отдельно как показатель первого месяца.
- Контакт-центр: две самостоятельные конверсии 20% → 40,5% и 51% → 73%; разные знаменатели явно объяснены.
- Лидогенерация: доля высокомаржинальных продуктов 43% → 52%. CPL описан как снижение более чем на 20%, без выдуманной точной стоимости.
- Юридический КЦ: 55,2% → 60,1% → 66,2% → 69,2%, четыре контрольные точки без вымышленных дат.
- Новые маршруты `/tools/` и `/tools/sales-economics/`. На главной в футере и в HTML-карте сайта появились ссылки на инструменты; sitemap расширен на два URL. На новых страницах — общие шапка, подвал, меню, серебряная эмблема, реквизиты ИП и плавающее окно связи. «Обсудить результаты» открывает это же окно.
- Для новых страниц добавлены canonical, OpenGraph, JSON-LD с хлебными крошками; SEO существующих страниц не переписывалось.

## Что исправлено при интеграции

1. Самостоятельные header/footer заменены существующими компонентами V27. CSS калькулятора изолирован классами `calc-*`, чтобы не менять остальные страницы. Сохранены компактные заголовки и читаемые поля ввода. Исправлена ссылка логотипа на главную.
2. Подключён общий `site.js`, без изменения самого файла. На страницах инструментов намеренно не подключён `analytics-config.js`: даже будущее заполнение глобальных ID само по себе не включит запись работы с финансовыми полями. Новые страницы не загружают внешние счётчики, не отправляют расчёты и не используют localStorage/sessionStorage/cookies для финансовых данных. Обращение через мессенджеры не содержит параметров расчёта. Копирование выполняется только по кнопке в локальный буфер обмена.
3. Исправлена безубыточность при нулевых постоянных расходах и нулевой модели: порог 0 сделок / 0 лидов. Отдельная подпись объясняет отсутствие положительного вклада от продаж. Для положительных расходов и нулевой/отрицательной маржи после бонусов порог остаётся недостижимым.
4. Исключено округление точного порога на лишнюю сделку из-за floating-point: проверен пример 0,07 / 0,01 = 7 сделок.
5. При неверном вводе очищаются все прежние результаты и подписи; конкретные поля отмечаются `aria-invalid` и связаны с сообщением. Предотвращена отправка формы по Enter. Денежные поля принимают дробные значения. Крайние сценарии конверсии подписаны как минимальная/максимальная конверсия.
6. Копирование проверено с настоящим Clipboard API и резервным способом при его отсутствии. После копирования сохраняется доступный фокус. Исправлены переносы больших сумм и контраст мелких подписей.

После интеграционных правок установщик калькулятора не запускался поверх изменённых новых файлов: его защита сравнивает их с исходным пакетом. Итоговая версия проверена отдельно. Проверка пяти графиков исходным скриптом `--check` проходит.

## Результаты проверок

- **59 HTML-страниц × 360, 390, 768, 1440 px = 236 открытий**. Горизонтальной прокрутки, ошибок JS/console, отсутствующих ресурсов, видимого личного телефона/ника не обнаружено. Реквизиты ИП — по одному блоку на каждой странице, фактический шрифт 11 px.
- 112 открытий мобильного меню и 236 открытий/закрытий окна связи. На новых страницах раздел «Инструменты» выделен в desktop и mobile меню.
- 20 проверок графиков: значения, пропорции полос, отсутствие выхода за шкалу; отметка 100% плана проверена на всех четырёх ширинах.
- **187 функциональных проверок калькулятора** на тех же четырёх ширинах. Проверены 0% и 100% конверсии, нулевая и равная бонусам маржа, прибыль/убыток, модель без расходов, точный дробный порог, неверный/пустой/отрицательный ввод, восстановление результата, сброс, реальное копирование и резервный способ на 390 px, Enter, CTA с клавиатуры, Escape и возврат фокуса на доступный элемент связи. Максимальные разрешённые значения не вызывают горизонтальной прокрутки.
- Пакетные математические тесты и 150 независимых моделей: проверены тождество прибыли и минимальность порога безубыточности. [Повторяемый тест](test-engine.mjs): `node docs/case-calculator-review/test-engine.mjs`.
- Контрольный пример: 24 ожидаемые сделки, 1 440 000 ₽ выручки, 648 000 ₽ валовой прибыли, 1 219 600 ₽ совокупных затрат и **220 400 ₽ результата до налогов**. Безубыточность — **16 сделок / 134 лида**. При конверсии 10% / 12% / 14% — результат 122 000 / 220 400 / 318 800 ₽.
- Данные формы не сохраняются и не отправляются; внешних запросов в проверенных сценариях не обнаружено. Аналитика не подключена, согласие существующего сайта не изменялось.
- **1711 внутренних ссылок и ресурсов** без ошибок, 59 корректно разбираемых блоков JSON-LD. Sitemap валиден, **56 уникальных URL**; прежние записи сохранены, добавлены только две новые.
- Контраст текста проверен на двух новых страницах и пяти кейсах при 390/1440 px: 14 открытий, 1159 текстовых узлов, после исправления замечаний — 0 нарушений выбранного порога WCAG AA для текста. Это автоматическая проверка текста, а не заявление о полной сертификации доступности.
- Существующие `styles.css`, `premium.css`, `site.js`, `analytics-config.js`, `privacy.html`, `robots.txt`, `llms.txt` и архитектура будущих разделов сохранены. Для кейсов проверено точное восстановление исходника при удалении добавленных графика и CSS-ссылки; для главной и HTML-карты — при удалении двух разрешённых ссылок.
- `node --check site.js`, `node --check tools/sales-economics/engine.mjs`, `node --check tools/sales-economics/ui.mjs`, `git diff --check` — успешно.

Даты `lastmod` старых страниц и корневой robots.txt не менялись: прежняя SEO-задача остаётся отдельной. Реальное состояние поисковых кабинетов этим этапом не проверялось.
